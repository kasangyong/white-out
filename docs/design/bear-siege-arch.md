# 곰 웨이브(공성) — 설계

- 기능명: 곰 웨이브 스테이지 + 프레스티지 스케일링
- 작성일: 2026-09-08
- brief: 없음 (요구사항은 대화에서 직접 수집, 아래 「전제」에 옮겨 적음)

## 전제 — 사용자가 확정한 것

1. 빙하 해금 이후, **일정 시간마다 자동으로** 곰 떼가 몰려온다
2. 곰은 **캠프 모닥불**로 진격한다. 가는 길에 플레이어를 만나면 플레이어도 공격한다
3. **웨이브 실패 = 그 겨울 종료.** 프레스티지·회차 기록은 남는다. 실패 60초 전부터 예고
4. **해금한 구획이 멀수록** 곰 수가 많아진다
5. 프레스티지마다 **웨이브 난이도 ↑ · 구획/강화 값 ×1.5 · 새 자원·구획 해금**

## 왜 이걸 만드는가 (실측 근거)

지금 난이도 곡선은 **h3에서 정점을 찍고 내려간다.**

| 구획 | 체온 감소/초 | 곰 함정 |
|---|---|---|
| h3 (28,000) | 1.22 | 2 |
| g1 (65,000) | 1.81 | **0** |
| g3 (350,000) | 3.14 | **0** |

가장 비싼 땅이 가장 안전하다. 추위는 창고에 고기만 쟁여 두면 해결되므로
후반에는 사실상 위험이 없다. 웨이브는 이 구멍을 정확히 메운다.

프레스티지도 마찬가지다. 지금은 `priceMul = (1+trade*0.15)*(1+prestige*0.25)` 뿐이라
**2회차는 같은 판을 1.25배 빨리 도는 것**이고 새로 볼 것이 없다.

## 결정 1 — 웨이브 상태를 기존 `storm` 에 얹을까, 따로 둘까

기존 `storm={t,fuel}` 은 신호탄 엔딩용이다. 상점을 잠그고, 창고를 인출 모드로 뒤집고,
60초 뒤 반드시 끝난다. 개념이 겹쳐 보이지만 **생애주기가 다르다** — 엔딩은 1회성 클라이맥스,
웨이브는 반복된다.

| 옵션 | trade-off |
|---|---|
| A. `storm` 을 `mode:'flare'\|'siege'` 로 확장 | 코드 한 덩이. 대신 두 모드가 서로 다른 분기를 20군데 만들고, 엔딩 중 웨이브가 겹치는 경우를 매번 따져야 한다 |
| B. **`siege` 전역 상태를 따로 둔다** | 상태가 하나 늘지만 각자 단순하다. 겹침은 "웨이브 중엔 신호탄 못 쏨" 한 줄로 끝난다 |
| C. 상태 없이 곰만 스폰 | 제일 싸다. 그러나 모닥불 연료·남은 곰·예고 타이머를 담을 데가 없어 HUD를 못 만든다 |

**추천: B.** 단, **연료 의미론은 storm 과 똑같이 쓴다** (0~100, 캠프에서 등짐의
나무 +16 / 고기 +34 자동 투입). 플레이어가 엔딩에서 이미 배운 조작이라 새로 가르칠 게 없다.
`siege={t, fire, round, left, warn}`.

**리스크:** 리필 코드가 두 곳(`storm`/`siege`)에 생긴다 → 공통 함수 `feedFire(get,set)` 로 뽑는다.

## 결정 2 — 진격 AI 를 기존 곰과 어떻게 나눌까

기존 곰은 `ox,oy` 주변을 배회하다 250 안에 들면 추격하고, 520 벗어나면 포기한다.
공성 곰은 **캠프를 향해 계속 걷고**, 길에서 플레이어를 만나면 때리고, 도착하면 불을 때린다.

| 옵션 | trade-off |
|---|---|
| A. **`b.siege=true` 로 같은 배열·같은 루프 안에서 분기** | 렌더 풀(`GFX.bears`)·처치·루트 코드를 전부 재사용. 루프에 `if` 하나 늘어난다 |
| B. 별도 `SIEGE[]` 배열 | 관심사 분리는 깔끔하나 메시 풀·처치·드랍을 통째로 복제해야 한다 |
| C. 모든 곰에 `goal` 좌표를 주고 통합(함정 곰은 goal=함정) | 가장 우아하지만 잘 돌던 함정 곰 동작을 다시 검증해야 한다 |

**추천: A.** 기존 곰 동작을 건드리지 않는 게 최우선이다(방금 배치·쿨다운 버그를 잡아 놨다).

동작 규칙:

```
공성 곰:
  leash 없음, ox/oy 배회 없음
  플레이어가 BEAR_AGGRO 안 → 플레이어를 향해 (기존 추격 그대로)
  아니면 → 캠프를 향해 직진
  캠프 반경 안 → 모닥불 공격 (BEAR_CD 간격, 연료 -SIEGE_BITE)
```

**리스크:** `b.mad` 가 `!shopOpen` 을 보고 있다. 상점을 열어 두면 진격이 멈추는 악용이 생긴다
→ 결정 5에서 상점을 잠근다.

## 결정 3 — 실패의 결과, 그리고 신호탄 엔딩과의 관계

| 옵션 | trade-off |
|---|---|
| A. 전부 초기화 (프레스티지까지) | 요구 그대로의 "게임 오버". 웨이브가 **자동**이라 자리를 비운 사이 350,000짜리 진행이 날아간다. 아이들 게임에서 가장 흔한 이탈 사유 |
| B. **그 겨울만 종료 — prestige·runs 유지, `S=fresh()`** | 체감은 게임 오버, 쌓은 메타는 남는다. `finish()` 가 이미 이 구조라 코드도 재사용 |
| C. 페널티만 (코인 30% 상실) | 안전하지만 "실패"가 아니라 "세금"이 된다. 긴장이 안 산다 |

**추천: B.** 종료 경로가 두 개가 되어 구조가 오히려 선명해진다.

| 경로 | 결과 |
|---|---|
| 신호탄 → 화이트아웃 60초 생존 | **구조됨.** prestige +1, 다음 겨울 |
| 웨이브 실패 (모닥불 0) | **얼어붙음.** prestige 그대로, 다음 겨울 |

즉 **웨이브를 버티는 동안 신호탄을 모으는 것**이 후반 게임이 된다. 늦어지면 진다.

**리스크:** 자리를 비우는 플레이. 완화 3종을 함께 넣는다 —
(1) 60초 예고, (2) 예고 중엔 오프라인 수익 정산 금지, (3) 첫 웨이브는 빙하 해금 후 120초 유예.

## 결정 4 — 곰 수·강도 공식

`freshPlots()` 기준 무료 구획은 **f1 하나**뿐이다. 빙하 해금(g1) 시점의 열린 구획은 7,
전부 열면 9.

| 옵션 | trade-off |
|---|---|
| A. 열린 구획 수 기준 | 요구("멀리 해금할수록")에 정확히 대응. 정수라 다루기 쉽다 |
| B. `frontier()` 반지름 기준 | 연속적이라 매끄럽지만, 구획을 사도 티가 잘 안 난다 |
| C. 라운드(웨이브 횟수) 누적만 | 해금과 무관해져 요구를 못 맞춘다 |

**추천: A + 라운드 + 프레스티지의 합.** 시작값(반드시 실측으로 조정):

```
곰 수   n     = 2 + (열린구획 - 6) + floor(round/2) + prestige*2      // g1 에서 3마리 시작
곰 강도 tough = 1 + round*0.15 + prestige*0.5                          // 처치 시간 배수
주기    T     = 180초                                                   // 예고 60초 포함
물어뜯기      = 연료 -12 / 1.7초                                        // BEAR_CD 재사용
```

처치 시간은 `need = GTIME.meat * tough / weaponMul()`.
창(×2.6) 기준 1라운드 곰 = 0.98초, 10라운드 = 2.4초.

**리스크:** 곰이 `frontier` 에서 캠프까지 **26.5초**(3500/132)면 도착한다. 예고 60초 중
후반 26초에 스폰해야 예고가 의미 있다 → 스폰은 **예고 26초 남았을 때**, 또는 캠프에서
`BEAR_SPD * 26` 거리에 스폰.

## 결정 6 — 프레스티지 스케일링

요구는 "비용 ×1.5". 지금 판매는 ×1.25 다. **그대로 곱하면 회차마다 실질 20% 씩 느려진다**
(1.5 / 1.25 = 1.2). 회차를 거듭할수록 벌 받는 구조는 프레스티지의 목적과 반대다.

| 옵션 | 회차당 진행 속도 | trade-off |
|---|---|---|
| A. 비용 ×1.5, 판매 ×1.25 (요구 그대로) | **0.83배 (느려짐)** | 난이도는 확실히 오르나 반복 동기가 사라진다 |
| B. **비용 ×1.5, 판매 ×1.5** | 1.0배 (동일) | 진행 길이는 그대로, 실제 변화는 웨이브 난이도와 새 구획. 숫자만 커지는 인플레 느낌은 감수 |
| C. 비용 ×1.5, 판매 ×1.8 | 1.2배 (빨라짐) | 고전적 프레스티지. 대신 "더 어려워진다"는 체감이 웨이브에만 걸린다 |

**추천: B.** 사용자가 원한 건 "다음 판이 더 어렵다"이고, 그 어려움은 **웨이브**가 담당한다.
비용/판매를 같이 올리면 진행 길이가 유지되어 밸런스 재측정 부담도 작다.

적용 지점 — `costScale = 1.5 ** S.prestige` 를 곱한다:
`costOf()` · `helperCost()` · `PLOTS[].cost` · `FLARE_COST` · 제작 재료(`costOfDef`).

**새 구획**은 `PLOTS` 에 g4·g5 를 미리 정의하고 `minPrestige` 로 잠근다.
`load()` 가 이미 `S.plots=Object.assign(freshPlots(), d.plots)` 로 병합하므로 옛 세이브도 안전하다.

**리스크:** 제작 재료까지 ×1.5 하면 창고 한도(`depotCap`)를 넘겨 만들 수 없는 물건이 생긴다
→ 재료는 스케일에서 **제외**하고 코인 비용만 올린다.

## 검증 계획 (오토파일럿, `update(dt)` 직접 구동)

숫자로 확인할 것:

1. **웨이브가 이길 수 있는가** — 창 + 사냥막사 + 나무 60개 비축으로 1~10라운드 생존 여부
2. **무기 없이 지는가** — 맨손이면 몇 라운드에 지는지 (져야 정상)
3. **곰 수 공식** — g1(3마리) → g3(6마리) → prestige1 g3(8마리) 실제 스폰 수
4. **모닥불 수지** — 곰 n마리 × 12/1.7초 vs 리필 속도(0.18초당 나무 16). 몇 마리부터 못 막는지
5. **26.5초 규칙** — 스폰 지점에서 캠프 도착까지 실제 시간
6. **티어 사다리 불변** — 나무 2.30 / 곰(창) 5.27 / 얼음 63.89 가 그대로인지
7. **프레스티지 2회차** — 비용 ×1.5, 판매 ×1.5 에서 첫 구획까지 걸리는 시간이 1회차와 같은지
8. **드로우콜** — 곰 8마리 동시 스폰 시 (현재 153)

## 결정 2를 어떻게 성립시키는가

곰은 이미 250 안의 플레이어를 우선 노린다. 그래서 **캠프에 서 있으면 곰이 제 발로 와서 죽는다** —
사거리(66~88)가 캠프를 덮으므로 불을 먹이면서 동시에 잡을 수 있다. 즉 집에 있으면 진다는 게 없다.

그래서 긴장의 축을 「전투 난이도」가 아니라 **「기회비용」**에 둔다.

```
빙벽 얼음 파밍 = 63.89 코인/초
g3 ↔ 캠프 편도  = 3200 / 165 ≈ 19초  (왕복 약 40초)
```

돌아가면 왕복 40초 + 전투 시간만큼 파밍을 잃는다. 안 돌아가면 불이 깎인다.
**"이번 웨이브는 그냥 무시하고 캘까?"** 가 매번 성립하도록 아래를 잡는다.

| 값 | 설정 | 근거 |
|---|---|---|
| 예고 | 60초 | 이동 준비 시간 |
| 스폰 | 예고 끝, **울타리 위 한 각도에 뭉쳐서** | 떼로 읽히고, 바깥에 있으면 그 자리에서 요격 가능 |
| 행군 | 3500 → 캠프 26.5초 | `BEAR_SPD 132` |
| 물어뜯기 | 연료 **-4 × tough** / 1.7초 | 곰 3마리 = 7/초 → 만재 100 에서 **14초** |
| 총 유예 | 60 + 26.5 + 14 ≈ **100초** | 한 번은 알아차릴 수 있는 창 |
| 리필 | 나무 +16 / 고기 +34, 0.18초 간격 (storm 과 동일) | 캠프에 있으면 89/초 — 지키러 오면 확실히 지킨다 |

곰 수·강도가 오르면 이 14초가 빠르게 줄어든다. 후반에는 무시할 수 없게 된다.

```
SIEGE_EVERY  = 180   // 웨이브 종료 후 다음 예고까지(초)

SIEGE_BITE   = 4     // 곰 1마리가 1.7초마다 깎는 연료 (× tough)
SIEGE_FIRE   = 100   // 모닥불 연료. 웨이브 사이에 만재로 회복
SIEGE_REWARD = 600   // 곰 1마리 처치당 코인 (× tough)

n     = 2 + (열린구획 - 6) + floor(round/2) + prestige*2     // g1 에서 3마리
tough = 1 + round*0.15 + prestige*0.5                          // 처치시간·물어뜯기 배수
```

전부 **실측으로 조정할 시작값**이다. 검증 계획 8항목은 위와 동일.

## 범위에서 뺀 것

- 새 자원(수정·온천수 등)과 새 구획 g4·g5 — 사용자 판단으로 보류
- 일꾼 피격 — 검증 범위가 두 배가 된다
- 곰 종류 분화(흰곰 등) — tough 배수로 대체
