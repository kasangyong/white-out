# 화이트아웃 — 생존 캠프

화이트아웃 서바이벌 광고의 그 루프(나무 베고 → 팔고 → 업그레이드 → 곰 잡고 → 팔고)를
**Arcade Idle** 장르 문법대로 구현한 웹 게임.
three.js 로우폴리 3D, 단일 HTML 파일, 빌드 도구 없음.

설계 근거는 [research.md](research.md) 참고.

## 실행

**`run.bat` 더블클릭.** 서버를 띄우고 브라우저를 열어 준다. 창을 닫으면 서버가 멈춘다.

직접 띄우려면:

```bash
python -m http.server 8123
```
→ 브라우저에서 `http://localhost:8123`

### index.html 을 그냥 더블클릭하면?

권장하지 않는다. `file://`에서는 브라우저가 두 가지를 막는다.

1. **로컬 ES 모듈 임포트** — `vendor/three.module.min.js`를 못 읽어 CDN으로 넘어간다(인터넷 필요)
2. **localStorage** — 막히면 진행이 저장되지 않는다 (크래시는 안 나고 조용히 넘어간다)

둘 다 서버로 열면 해결된다.

> 파일을 수정한 뒤 화면이 그대로면 브라우저 캐시다. **Ctrl+Shift+R**로 강제 새로고침.
> (`python -m http.server`는 no-cache 헤더를 보내지 않는다)

**네트워크는 필요 없다.** three.js도 캐릭터 모델도 전부 같이 들어 있다.

```
index.html
vendor/three.module.min.js       three.js 본체
vendor/three.core.min.js
vendor/jsm/loaders/GLTFLoader.js       모델 로더
vendor/jsm/utils/SkeletonUtils.js      스킨드 메시 복제
vendor/jsm/utils/BufferGeometryUtils.js  (GLTFLoader 가 요구)
assets/Rogue_Hooded.glb          플레이어 캐릭터 (KayKit, CC0)
assets/axe_1handed.gltf + .bin + barbarian_texture.png   도끼
assets/KAYKIT_LICENSE.txt
```

## 3층 구조

조사 문서의 Arcade Idle 정의를 그대로 따랐다.

- **액티브** — WASD 이동, 근접 자동 채집, 머리 위로 쌓이는 **스태킹**, 스택 한도, 판매대 운반
- **아이들** — 일꾼 최대 6명이 숲에서 자동으로 채집·판매, 최대 4시간 오프라인 수익
- **메타** — 12종 강화 트리, 구획 9개 개간, 구조 신호탄(최종 목표) → 프레스티지

## 진행 구조 — 캠프에서 사방으로

**울타리로 둘러싸인 캠프에서 시작해 바깥으로 넓혀 나간다.**
구획(plot)을 '동심 띠'로 두면 울타리는 항상 **하나(현재 경계)**뿐이고,
확장이 곧 그 울타리가 밀려나는 것이 된다. 관문·구역벽 같은 별도 장치가 필요 없다.

```
        캠프(중심, r<250) ── 상점·모닥불, 여기선 체온이 공짜로 찬다
   ↓ 반지름이 커질수록 바깥
 f1 250–450   무료      캠프 앞 숲
 f2 450–620   300       숲 바깥
 f3 620–780   1,200     깊은 숲
 h1 780–930   4,000     사냥터
 h2 930–1070  11,000    바깥 사냥터
 h3 1070–1200 28,000    설원
 g1 1200–1310 65,000    빙하 입구
 g2 1310–1400 150,000   빙하 지대
 g3 1400–1480 350,000   빙벽
```
### 엔딩 — 화이트아웃을 버텨라

코인만 모아서 끝나면 클라이맥스가 없다. 신호탄은 **코인 60,000 + 재료(철 35·석탄 25·나무 60)**로
만들고, 쏘는 순간 게임 제목 그대로 **화이트아웃**이 몰아친다.

- 하늘이 하얗게 죽고 안개가 조여든다. 캠프 근처도 체온이 급격히 떨어진다
- **60초 동안 캠프 모닥불을 꺼뜨리지 않아야** 구조된다 (연료 11/초 감소)
- 불 곁에 서면 등짐의 나무(+16)·고기(+34)가 자동으로 타 들어간다
- **폭풍 중에는 상점이 잠기고, 창고는 반대로 작동한다** — 넣는 곳이 아니라 꺼내는 곳
- 필요량은 나무 약 42개. 등짐 한 번으로는 모자라 불과 창고를 오가야 한다
- 실패해도 신호탄은 남는다. 연료를 더 쟁여서 다시 쏘면 된다

- 이동은 경계 밖으로 못 나가되, 벽에 부딪히는 대신 **원을 따라 미끄러진다**
- 상점이 캠프(중심)에 있어 갇혀도 강화는 언제나 살 수 있다. <kbd>E</kbd> 로 어디서나 열린다
- 상단 HUD는 가로 구역바 대신 **원형 미니맵** — 동심 구조와 맞다

## 자원 7종과 제작

자원이 전부 '팔아서 코인'으로만 흐르면 코인의 다른 이름일 뿐이다.
자원마다 고유한 쓸모를 붙였다.

| 자원 | 획득 | 곡괭이 | 판매가 | 쓸모 |
|---|---|---|---|---|
| 🪵 나무 | 나무 군락 | — | 4 | 함정 미끼 · 거의 모든 제작 |
| 🪨 돌 | 바위 군락 | 나무 | 9 | 화로·대장간·돌도구 |
| 🟫 가죽 | 곰 (고기와 함께) | — | 26 | 장갑·모피코트·사냥막사 |
| 🥩 고기 | 곰 (함정) | — | 30 | 체온 회복 |
| ⚫ 석탄 | 석탄 광맥 | 돌 | 44 | 화로 |
| ⛓️ 철 | 철 광맥 | 돌 | 95 | 강철 도구·썰매 |
| 🧊 얼음 | 얼음 군락 | — | 180 | 최상위 환금 |

### 곡괭이 티어가 광물을 막는다

마인크래프트와 같은 구조다. 맨손으로는 돌을 못 캔다.

```
맨손                    → 나무 6            → 나무 곡괭이 → 돌 채집
나무 곡괭이 + 나무 6·돌 10 → 돌 곡괭이   → 석탄·철 채집
```

### 판매대 vs 창고 — 매 왕복의 선택

- **판매대**(노란 발판) → 코인 → 강화
- **창고**(캠프 안 파란 발판) → 재료 → 건물·도구

같은 자원을 코인으로 바꿀지 재료로 쌓을지 매번 갈린다.

**보관 한도는 자원 1종당 30**, 창고 건물을 지으면 90, 그 뒤로는 **창고 증축**으로 +50씩 늘린다.
한도에 걸리면 넣지 않고 알린다.
**창고의 재료는 클릭하면 등짐으로 도로 꺼낼 수 있다** — 넣기만 되면 잘못 넣은 자원이 영영 묶인다.

> 처음엔 보관이 무제한이고 꺼낼 수도 없었다. 게다가 **고기·얼음은 어떤 제작에도 안 쓰여서**
> 창고에 넣는 순간 팔 수도 쓸 수도 없이 사라졌다(얼음은 개당 180!).
> 한도·꺼내기를 넣고, 고기·얼음을 쓰는 건물(훈연장·얼음 저장고)을 추가해 막다른 자원을 없앴다.

### 건물 8채 + 반복 제작 1종

| 건물 | 재료 | 효과 | 선행 |
|---|---|---|---|
| 📦 창고 | 나무 10 | 등짐 +4 · 보관 한도 30→90 | — |
| 🪚 제재소 | 나무 26 · 돌 10 | 나무 판매가 ×1.6 | 창고 |
| 🔥 화로 | 돌 20 · 석탄 6 | 철·석탄 ×1.5 | 창고 |
| ⚒️ 대장간 | 돌 32 · 철 10 | 철 도구 해금 | 화로 |
| 🧵 무두질대 | 나무 22 · 가죽 6 | 가죽 ×1.8 · 모피 해금 | 창고 |
| 🏹 사냥막사 | 나무 30 · 가죽 10 · 철 6 | 함정 재가동 | 무두질대 |
| 🍖 훈연장 | 고기 16 · 나무 14 · 돌 8 | 고기 판매가 ×2.0 | 창고 |
| 🧊 얼음 저장고 | 얼음 24 · 나무 18 · 돌 12 | 오프라인 4→10시간 | 창고 |
| 🏗️ 창고 증축 | 나무 24·돌 14 (×1.7^Lv) | 보관 한도 +50 · **반복** | 창고 |

> **제작 쪽 유일한 반복 소비처가 창고 증축이다.** 나머지는 전부 1회성 해금이라,
> 이게 없으면 후반에 재료가 쌓이기만 하고 쓸 데가 없어진다.

> **초반 비용은 등짐 용량으로 역산한다.** 처음 등짐이 3칸이라
> 창고 25개는 왕복 9회였다. 10개(왕복 4회)로 낮췄고, 사면 바로 +4칸이라
> 그 뒤로는 눈덩이처럼 빨라진다. 나무 곡괭이는 6개(왕복 2회)로 가장 먼저 손에 들어온다.

### 도구 7종

곡괭이 2종 외에 돌도끼(채집 ×1.4) · 강철도끼(×1.9) · 가죽장갑(사거리 +26) ·
모피코트(체온 감소 −45%) · 썰매(등짐 +8).
강철도끼와 썰매는 **대장간**, 장갑·모피는 **무두질대**가 있어야 만든다.

반복 제작 2종도 도구 탭에 있다 — 🔨 도끼 벼리기(채집 +8%/Lv, 돌·철),
🎽 등짐 보강(+2칸/Lv, 가죽·나무). 창고 증축과 함께 **재료의 상시 소비처**다.

상점은 <kbd>E</kbd> 하나에 **강화 / 건물 / 도구** 세 탭으로 들어 있다.

## "No resource left behind"

초반 자원이 후반에 죽지 않도록 두 개의 영구 수요를 걸어 놨다.

```
나무 → 함정 미끼(3개) → 곰 → 고기
고기 → 전초 모닥불 → 체온 → 바깥 띠에서 버티기
```

**소비처는 그 띠 안에 둔다.** 사냥터·빙하 띠에도 나무를 심어서, 함정에 넣을 나무를 구하러
맵을 가로지르지 않아도 되게 했다. 전초 모닥불은 고기(+45)가 효율적이지만 나무(+15)도 태울 수 있다 —
연료가 떨어졌다고 바깥에서 발이 묶이면 안 된다.

**체온은 '캠프에서 얼마나 멀리 있는가'로 정해진다.** 숲 끝(r=780)부터 서서히 떨어지고
빙벽에서 가장 빠르다. "빙하 구역에서만 감소" 같은 임의 규칙이 사라지고 테마와도 맞는다 —
불에서 멀어질수록 춥다.

## 밸런스 — 실측으로 맞췄다

초기 버전은 **곰 사냥이 나무 팔기보다 14% 손해**였다. 고기값(18)이 나무 5개(20)보다 쌌고,
함정 나무를 구하러 숲(x~450)에서 함정(x~1520)까지 왕복 13초를 걸어야 했다.

오토파일럿으로 각 루프를 실제로 돌려 측정한다(`goTo`/`fill`로 `update()`를 그대로 구동).

| 루프 | 초당 코인 | 배수 |
|---|---|---|
| 나무 | 2.54 | 1.0 |
| 곰 (구역 내 조달) | 7.57 | **3.0** |
| 얼음 (체온 관리 포함) | 15.51 | **6.1** |

상위 티어가 항상 더 벌어야 한다. 한 번 뒤집히면 그 콘텐츠는 아무도 안 한다.

### 초반 페이싱 — 첫 강화까지 5초

오토파일럿으로 "첫 강화를 살 때까지"를 재면 처음엔 **80초, 그마저 도달 실패**였다.
원인 셋을 모두 고쳤다.

| 문제 | 조치 |
|---|---|
| 구획 울타리가 상점 가는 길을 막음 | **상점을 캠프(중심)로** — 갇혀도 늘 닿는다 |
| 첫 강화 25코인 = 왕복 3회 | 도끼 12 / 등짐 24 로 인하 → **왕복 1회** |
| 강화 하나에 캠프 왕복 8초 | <kbd>E</kbd> 로 어디서나 상점 |

결과: 첫 강화 **5초**, 60초 안에 8개 구매(약 7초 간격).

### 초반이 길다는 피드백 — 등짐이 아니라 회수 기간이 문제였다

왕복 한 번(5.7초)을 쪼개 보면 **이동 51% · 채집 49%**로 반반이다.
등짐만 늘리면 이동 시간만 줄고 채집 시간은 그대로라 한계가 있다.

진짜 원인은 따로 있었다. 300코인까지 걸리는 시간을 정책별로 재면

| 정책 | 시간 |
|---|---|
| 강화 안 사고 저축만 | 145초 |
| 도끼 5렙 | 147초 |
| 등짐 5렙 | **198초** |

**강화를 사면 오히려 느렸다.** 회수 기간이 60~120초라 초반 창에서는 손해였다.
사도 체감이 없으니 "오래 걸린다"가 된다.

| | 이전 | 지금 |
|---|---|---|
| 기본 등짐 | 3 | **4** |
| 등짐 강화 | +1/Lv | **+2/Lv** (회수 절반) |
| 동시 벌목 | 900 | **140** (채집 시간을 반으로 줄이는 유일한 수단인데 너무 멀었다) |
| 첫 구획 | 300 | **180** |

첫 구획까지 **145초 → 86초**(저축만 기준).

> 단, "저축만이 가장 빠르다"는 건 **고정 목표까지의 시간**을 잰 착시다.
> 옳은 지표는 일정 시간 동안 번 총액이다 — 240초 순자산으로 재면
> 강화 없음 396 / 등짐만 672 / 도끼만 896 / **혼합 1,032**로 강화가 확실히 이득이다.

> 얼음은 처음에 4.17/s로 **곰보다 낮았다** — 체온 심부름이 수익을 다 먹어서다.
> 얼음값 80→180, 체온 감소 5→3.5/s, 얼음 노드 3→4개로 고쳤다.

**구획·신호탄 가격은 아직 플레이테스트로 검증하지 않았다.** 위 초당 수익에 맞춰 계산만 해 둔 값이다.

## 렌더러 (three.js r185)

게임 로직과 렌더러는 **완전히 분리**돼 있다. `update(dt)`는 three.js를 전혀 모른다.
2D 캔버스에서 3D로 갈아끼울 때 `draw()` 계열만 교체했고, 로직 테스트 22개는 그대로 통과했다.

- **에셋 0** — 나무·곰·캐릭터·텐트 전부 원시 도형(cone/sphere/capsule/box)을 코드로 조립
- **셀 셰이딩** — 4단 gradientMap + `MeshToonMaterial`. 넓은 지면만 램버트(툰이면 밴딩이 보인다)
- **지오메트리 10개**를 전 오브젝트가 공유 (드로우콜 ~300, 삼각형 ~10k)
- **성능** 평균 4.85ms/프레임. 시작 시 셰이더·섀도우맵을 미리 굽는다
  (`renderer.compile` + 워밍업 렌더 → 첫 프레임 158ms → 55ms, 그마저 시작 화면 뒤로 숨김)
- **카메라** — 46° 부감 추종. 16:9 기준 거리를 잡고 세로로 긴 창에서만 완만히 물러난다
  (가시 폭을 강제로 맞추면 세로 창에서 카메라 고도가 1,800까지 올라가 캐릭터가 점이 된다)
- **2D 오버레이 캔버스** — 게이지·떠오르는 글자·코인 연출은 3D 좌표를 스크린으로 투영해 그린다
- 그림자는 플레이어를 따라다니는 직교 섀도우 카메라 하나로 처리

### 캐릭터

**플레이어는 실제 모델, 일꾼은 절차적**이다. `makeChar(..., isPlayer)` 한 인자로 갈린다.

| | 플레이어 | 일꾼 |
|---|---|---|
| 모델 | KayKit `Rogue_Hooded.glb` (CC0) | 코드로 조립한 도형 |
| 애니메이션 | `Idle` / `Walking_B` / `1H_Melee_Attack_Chop` 가중치 블렌딩 | 사인파 팔다리 스윙 |
| 도끼 | `handslotr` 본에 KayKit 도끼를 매단다 | 오른팔 피벗의 자식 |

**왜 일꾼은 모델을 안 쓰나** — 일꾼까지 GLB로 하면 스킨드 메시가 **42개**(7명 × 6)가 된다.
내장 GPU에서 부담이 크고 일꾼은 멀리서 배경으로 보이는 대상이다. 6개로 억제했다.
좋은 GPU에서 다 써 보고 싶으면 `GLB_HELPERS=true`.

모델 규격은 실측으로 정했다 — 스킨 적용된 정점 기준 키 2.223유닛 → `CHAR_SCALE=34.18`
(월드 76유닛, 나무 대비 0.46). `Box3.setFromObject`는 스킨드 메시에서 **레스트 포즈**를 재므로 믿으면 안 된다.

절차적 캐릭터(일꾼)에서 배운 것:
- 팔·다리는 **피벗 그룹**에 매단다. 실린더를 직접 돌리면 가운데를 축으로 돌아 어색하다
- 눈·코는 머리 구(r=14)보다 **바깥에** 둬야 한다. 안쪽이면 통째로 묻힌다
- 후드는 씌우는 구가 아니라 **얹는 모자**. 구를 통째로 씌우면 얼굴이 사라진다
- 스택은 머리 위로 솟되 살짝 뒤로. 몸통 뒤면 가려지고, 앞이면 얼굴을 덮는다

### 발밑 링

로그 캐릭터가 초록이라 초록 나무 사이에서 위치를 놓친다.
플레이어에 금색 링을 깔았다 (`GLB_HELPERS=true`면 일꾼은 파란 링).

### three.js 로딩 방식

r185에는 UMD 빌드가 없어 `<script type="module">`로 ESM을 불러온 뒤 `window.THREE`에 올리고,
게임 본체는 클래식 스크립트로 돌린다(전역 스코프 유지 → 콘솔에서 디버깅 가능).

```js
let T; try{ T=await import('./vendor/three.module.min.js'); }      // 로컬 우선
        catch(e){ T=await import('https://cdnjs.cloudflare.com/…'); }  // 없으면 CDN
window.THREE = T;
```

`three.module.min.js`가 `./three.core.min.js`를 상대경로로 부르므로 두 파일이 같은 폴더에 있어야 한다.
둘 다 실패하면 시작 화면에 안내가 뜬다.

### 일꾼도 키운다

일꾼은 처음에 **나무만, 3개씩, 가장 가까운 판매대**로 다닌다. 셋 다 강화 대상이다.

- 🎓 **훈련** — 나무 → +돌 → +석탄·철. **내 곡괭이 등급을 넘을 수 없다**
  (Lv1은 나무 곡괭이, Lv2는 돌 곡괭이가 있어야 산다)
- 🛒 **짐수레** — 운반 +2/Lv
- 📯 **호각** — 이동 속도 +14%/Lv

일꾼은 **가치÷거리**로 목표를 고르므로, 훈련시키면 알아서 비싼 광물을 찾아간다.
개간한 땅(현재 울타리) 안에서만 움직인다.

> **짐수레는 원거리에서만 값을 한다.** 400초 수익으로 재면 나무만 캘 땐 +19%,
> 훈련2로 철을 캐러 갈 땐 **+79%**. 일꾼 채집이 개당 1.5초 고정이라
> 왕복이 짧으면 운반량을 늘려도 채집 시간만 늘어난다.

400초 수익: 기본 1,340 → 훈련2 5,320 → 훈련2+짐수레4 **9,500**.

### 곱해지는 3종 (동시 벌목 · 묘목 · 한 아름)

같은 군락에서 4초간 캔 개수를 실측하면 **3개 → 28개 (9.3배)**.
사거리를 올리면 군락 안에서 잡히는 그루가 4 → 7로 늘고, 동시 벌목이 그만큼 한꺼번에 캔다.

## 자원은 '군락'으로 심는다

흩어 놓으면 사거리·동시 벌목 업그레이드가 **아무 효과가 없다.**
처음에 나무를 흩어 심었더니 사거리를 194까지 올려도 2그루밖에 안 잡혔다.

군락은 중심 좌표 하나 + 나선(황금각) 배치로 만든다. 그루 수만 바꾸면 알아서 뭉친 모양이 되고,
'묘목'으로 그루를 늘리는 것도 자연스럽게 붙는다.

```js
GROVE_DEF = [ ['f1','wood',[[1.1,350],[2.6,350],[4.1,350],[5.6,350]],4], ... ]
                            └ (각도, 반지름) — 띠마다 사방에 흩어 놓는다
grovePos(g,i) → 군락 내 나선 배치 (r = 46 + 18·√i)
```

묘목으로 늘어날 그루까지 **미리 만들어 두고 `need` 로 잠근다** — 구획과 같은 방식이라
업그레이드를 사도 월드를 다시 짓지 않는다(함정 미끼가 초기화되면 안 되니까).

> `Math.round`를 쓴다. `1.16` 등이 이진수로 정확하지 않아 `floor`면 `25×1.16`이 28로 깎인다.

## 검증

`update(dt)`를 고정 dt로 구동하는 결정론적 방식 **16개, 전부 통과.**
로직 21개(이동·채집·스택한도·판매·리스폰·상점개폐·비용곡선·관문차단/해금·함정→곰→고기·
체온3종·일꾼자동화·오프라인수익·저장복원·프레스티지·힌트) +
3D 8개(성능·로컬로딩·스택동기화·곰/일꾼 메시풀·도끼리그·NaN자가복구·루프에러).

### 여기서 잡힌 실제 버그

| 증상 | 원인 |
|---|---|
| 지면이 통째로 갈색 | 울타리 링을 `TorusGeometry(1, 5)` 로 만들고 `scale.set(fr,fr,1)` 로 늘렸다. **튜브 두께까지 450배**가 돼 거대한 도넛이 지면을 덮었다. 튜브를 반지름 비례(0.011)로 잡고 균등 스케일 |
| 구획이 영원히 안 사짐 | 매 프레임 `for(const p of PLOTS) p.prog=0` 로 **진행 중인 구획의 진행도까지** 지웠다 |
| 걷는 방향과 바라보는 방향이 반대 | GLB 모델 정면을 −Z로 **잘못 판단**하고 `rotation.y=PI`를 넣었다. 실제 정면은 +Z (망토가 로컬 −Z쪽에 달려 있다 = 등이 −Z). 스크린샷으로 얼굴/뒤통수를 눈대중한 게 화근 — **망토·장비 위치 같은 비대칭 지형지물로 판정할 것** |
| **강화 구매 클릭이 전혀 안 먹힘** | `renderShop()`이 매 프레임 `innerHTML=''`로 행을 재생성. `mousedown`과 `mouseup` 사이(사람 클릭 50~150ms = 3~9프레임)에 요소가 사라져 `click`이 성립하지 않았다 |
| 첫 프레임에 게임이 멈춤 | `syncUI`가 참조하는 DOM 요소가 없어 예외 → rAF 재등록 실패 |
| 창을 줄였다 키우면 하늘만 나옴 | 창 크기 0 → `aspect`가 NaN → 카메라 좌표에 눌러앉음 (자가복구 추가) |
| 함정이 안 보임 | `initThree()`가 `TRAPS`보다 먼저 실행돼 빈 배열을 읽음 |
| 강화 비용이 설계값과 어긋남 | `25 × 1.16 = 28.9999…` → `floor`로 28 (`round`로 변경) |
| ESC가 안 먹힘 | `update()`가 매 프레임 근접 판정으로 상점을 다시 켬 |

> **매 프레임 DOM을 다시 만들면 클릭이 죽는다.** 값만 갈아 끼우고 요소는 유지할 것.
> 그리고 `el.click()`으로 하는 테스트는 이 버그를 **못 잡는다** — 실제 마우스 좌표로 눌러 봐야 한다.

### 나무 지오메트리는 합쳐서 쓴다

나무 한 그루를 줄기+잎3+눈모자 = 메시 5개로 만들었더니, 묘목으로 76그루가 되자
**드로우콜이 663**까지 올랐다. 정점 색(`vertexColors`)으로 한 덩어리로 머지해
그루당 1개로 줄이고 장식물을 130→70개로 깎아 **276**으로 내렸다. 2톤 잎·눈모자는 그대로 보인다.

```js
buildTreeGeo()  // BufferGeometryUtils.mergeGeometries + 파트별 color 속성
```
머지하려면 파트들의 속성 구성이 같아야 한다 — `deleteAttribute('uv')` 필요.

### 머티리얼은 반드시 캐시할 것

같은 실수를 두 번 했다. 메시마다 `new MeshToonMaterial`을 만들면
캐릭터 5명에 머티리얼 **73개**가 생기고 첫 프레임이 **535ms** 튄다(셰이더가 그만큼 컴파일된다).
색·텍스처를 키로 캐시해 37개로 줄였다. `toonC()` / `CHAR_MAT` 참고.

## ⚠ 성능은 직접 확인할 것

프레임 시간을 **신뢰할 수 있게 재지 못했다.** 개발에 쓴 브라우저 창이 숨겨진 상태라
`renderer.render()`가 GPU 작업을 큐에 넣고 바로 반환하고, `gl.finish()`로 동기화해도
"캐릭터 0명 413ms / 1명 8ms" 같은 모순된 값이 나왔다.

확실한 것은 구조적 수치뿐이다.

| | 값 |
|---|---|
| 보이는 스킨드 메시 | 6 (일꾼까지 GLB면 42) |
| 드로우콜 | ~276 (전 구획 해금 + 묘목MAX + 일꾼 6명) |
| 삼각형 | ~33,000 |
| 머티리얼 / 셰이더 프로그램 | 37 / 22 |
| 부팅 | ~1.7초 (3.6MB GLB 파싱 + 셰이더 굽기, 시작 화면 뒤) |

**끊기면 `GLB_HELPERS`는 이미 false이니, 다음으로 그림자(`renderer.shadowMap.enabled`)를 꺼 보라.**
장식물 130개도 줄일 여지가 있다.
